# قَريض

**ديوانُ الشِّعرِ العربيِّ ومُساجَلتُه** — <https://qarid.avicenna.space>

قَريضٌ اسمٌ قديمٌ للشِّعرِ نفسِه. هذا الموقعُ شيئان في واحد:

- **ديوانٌ يُتصفَّح**: 238,733 قصيدةً و3,371,410 بيتًا لـ6,941 شاعرًا، مرتَّبةً
  بالعصرِ والبحرِ والغرضِ والرَّوِيِّ، مع بحثٍ في المتنِ كلِّه.
- **مُساجَلة**: يُنشِدُ الخصمُ بيتًا، وعليك أن تُجيبَه ببيتٍ يبدأُ برَوِيِّه.
  أربعُ مراتب — مُبتدئ، شاعر، فحل، سيف — وساعةٌ ونفَسٌ وترسانةٌ تُبنى ممّا
  تحفَظ.

وفيه أيضًا **بيتُ اليوم**، و**التَّحفيظ** (تكرارٌ متباعدٌ لما تُريدُ حفظَه)،
و**التَّجوال** بين الأبياتِ على غيرِ هُدًى، و**بطاقاتٌ** تُشارَك.

<img src="docs/media/poem.png" alt="صفحة القصيدة" width="100%">

القصيدةُ كما تُقرأ: صدرٌ وعجزٌ وشمسةٌ بينهما، بالتشكيلِ وثلاثةِ مقاديرَ للخطّ.

<img src="docs/media/poets.png" alt="صفحة الشعراء" width="100%">

الشُّعراءُ على رِفِّ الحروف، بأعدادِهم وقيودِ عصورِهم، مرتَّبين بالأكثرِ قصائد.

## المُساجَلة

<img src="docs/media/duel.png" alt="المساجلة" width="100%">

بيتُ الخصمِ بحاشيةِ اللازَورد، والحرفُ المطلوبُ في مِحرابِه، وثلاثةُ أقلامٍ هي
أرواحُك. ويكفي أن تكتبَ الصدرَ وحدَه — البيتُ يُوجَد. وفي الإعدادِ **وضعُ
التدريب**: تكتبُ أوّلَ كلمةٍ فيرتفعُ إلى جانبِك رِفٌّ من أبياتٍ حقيقيّةٍ تصلحُ
جوابًا، وثمنُه مُعلَنٌ — نصفُ النقاط.

## البحثُ السريع

## الحسابُ والمِلَفّ

الديوانُ كلُّه يُقرأُ بلا حساب. وإنّما الحسابُ لأمرين: أن تُساجِلَ صديقًا
باسمِك، وأن تكونَ لك صفحةٌ عليها اسمُك — `#/u/<اسمك>` — فيها تاريخُ انضمامِك،
وسِجِلُّ مُساجَلاتِك، وترسانتُك إن شئتَ رفعَها. ولا بريدَ في القريض، فلا
استعادةَ لكلمةِ سِرٍّ ضاعت.

## مُساجَلةُ الأصدقاء

<img src="docs/media/room.png" alt="غرفة مساجلة" width="100%">

من الإعدادِ تختارُ «ضدَّ صديق»، فتفتحُ غرفةً وتنتقي بيتَ الافتتاح، فيصيرُ لك
رمزٌ من ستّةِ أحرفٍ يُنطَق ورابطٌ يُرسَل. وللدخولِ بابان:

- **الرابط**: ما أرسلتَه يحملُ مفتاحَ الغرفةِ معه، فمن فتحَه جلسَ في المقعدِ
  الثاني من فورِه.
- **الطَّرْق**: ومن لم يبلغْه إلّا الرمزُ منطوقًا — أمليتَه عليه في مجلسٍ أو
  في هاتف — دخلَ من «انضمّ إلى غرفةٍ بالرمز»، ثمّ **«اطرقِ البابَ»**؛ فيرى
  صاحبُ الغرفةِ اسمَه على شاشتِه فيَقبلُ أو يَرفض. الرمزُ يدلُّ على الغرفة،
  والإذنُ هو الذي يفتحُها.

والحَكَمُ في الغرفةِ هو الخادمُ وحدَه: الساعةُ عندَه، والدَّورُ عندَه، ولا
يُقبَلُ بيتٌ إلّا بحُكمِه. ولذلك لا يُخسِرُك انقطاعُ الشبكةِ شيئًا — لا
يُنهي دورَك إلّا انقضاءُ وقتِه — ولصاحبِ الغرفةِ أن يُغلِقَها متى شاء.

## Dev notes (English)

A single npm package: **Vite 7 + React 19** client, **Hono 4** server run
directly by **Node 26** (TS type-stripping — there is no server build step),
reading one **read-only SQLite artefact** through `node:sqlite` with **FTS5**
over it, plus one small **writable** database for accounts and rooms. The only
runtime dependencies past that list are `@hono/node-ws` (the مساجلة socket) and
the Capacitor packages the Android shell needs.

### Commands

| command | what it does |
|---|---|
| `npm run dev:server` | API on **5750** (`--watch`, reads `.env`) |
| `npm run dev` | Vite on **5751**, proxies `/api`, `/healthz` and `/ws` → 5750 |
| `npm run typecheck` | `tsc -p tsconfig.json` |
| `npm test` | vitest — **1241 tests / 59 files** over `data/fixture.db` |
| `npm run build` | `tsc` + `vite build` → `dist/` |
| `npm run smoke` | `tools/screenshot.mjs` — starts the real server, walks every route in headless Chromium, fails on any console error |
| `npm start` | production server (reads `.env`, defaults to **8010**) |

The done bar, all four green before any commit that ships:

```sh
npm run typecheck && npm test && npm run build && npm run smoke
```

`node tools/screenshot.mjs [--no-build] [--mobile] [--full] [--port N] [--db PATH] [--routes home,browse,…]`
is the smoke walk. `--mobile` is a *phone*, not a narrow window (`hasTouch` +
`isMobile`, so `(pointer: coarse)` matches). It kills **only** the child it
spawned — never `pkill -f server/index.ts`, the whole suite shares that path.

### Layout

```
shared/     the contract layer — arabic.ts (the ONLY normalizer), schema.ts
            (zod; every DTO and every persisted shape), meters/eras/themes/
            letters, format.ts (العدد والمعدود lives here, never at a call
            site), rng.ts (seeded sfc32), constants.ts (the pinned corpus rev)
scripts/    ingest: readers → transform (pure, tested) → build (3 passes)
server/     Hono. app.ts is listen-free so tests drive app.request(); routes/
            are mounted at the one marked block; dto.ts is the only place a
            column name is spelled; origin.ts is the CSRF/CORS guard;
            rooms.ts is the server-authoritative مساجلة
client/     React, hash-routed, RTL. BaytPlate is the only بيت renderer;
            training/ holds all of التحفيظ's arithmetic; share/renderCard.ts
            is the only share-card renderer; sw/sw.ts is the PWA worker;
            platform/ is the native (Capacitor) shim
android/    the Capacitor project — space.avicenna.qarid
docs/       v2.md, roadmap-mobile.md, design-server.md, design-ux.md,
            amendments.md (amendments win), releases/, media/
tools/      screenshot.mjs (the smoke walk) + smoke-seed.json
```

Read `CLAUDE.md` before changing anything — it carries the invariants that were
expensive to learn (header ordering under `compress()`, grid automatic minimums,
the two writers of `qarid:v1:training`, why `ORDER BY RANDOM()` is banned, why
`Ctrl+K` cannot live in `useKeyboard`).

### The corpus artefact

`data/qarid.db` is **gitignored and rebuildable**, not a source file. Build it:

```sh
node scripts/ingest/index.ts fetch     # verify data/raw/*.parquet (pinned rev + sha256)
npm run ingest                         # ~155 s, peak RSS 836 MB → 1.48 GiB
npm run ingest:fixture                 # data/fixture.db for the test suite
```

Ingest is Node, not Python, so it imports the same `shared/arabic.ts` the server
does — there is exactly one normalizer and it cannot drift. Three passes: pass 0
decides which copy of each duplicate قصيدة survives, then the rows land, then the
derived tables (`game_baits`, `combo_counts`, the FTS index, and the precomputed
`meta_json` / `stats_json` blobs).

**Rebuild to a side path when a server has the file open**, or SQLite will hand
you `database is locked` half way through and leave a truncated artefact:

```sh
node scripts/ingest/index.ts build data/raw/*.parquet data/qarid.build.db \
  && mv -f data/qarid.build.db data/qarid.db \
  && systemctl --user restart qarid.service
```

A missing artefact is tolerated at boot: `/healthz` and the static client still
serve, `/api/*` answers 503. systemd never crash-loops on a fresh box.

### What's inside

| fact | measured |
|---|---|
| corpus | **238,733** قصيدة · **3,371,410** بيتًا · **6,941** شاعرًا · **1,709,893** game-playable أبيات |
| built from | 254,630 source rows — 15,891 duplicate قصائد and 6 verse-less poems dropped; 56 curated شاعر aliases folded |
| lookups | 12 عصور · 32 meters (16 بحور + التفعيلة/الموشح/النثر/الفولكلور) · 18 أغراض |
| artefact | 1.48 GiB at `page_size = 8192`, deterministic (`build_id bbe2f944`) |
| tests | **1241** across 59 files, over a fixture built by the real ingest path |
| bundle | 1.1 MB `dist/` (woff2 only) · release APK 4.5 MB |

**Latency, p50, warm, over HTTP on the real corpus: every route is ≤ ~23 ms**
against a 150 ms budget — `/api/meta` 0.7 · `/api/stats` 3.0 · `/api/search`
1.3–20 · `/api/poems` filtered 5.1 · `/api/poets` 6.9 · `/api/baits` 13–22 ·
`/api/train/candidates` 15 · the duel's three routes 1.3–11. The one cold cliff
left is a *filtered* `/api/facets` combination (94–232 ms on its first call, then
memoised for the life of the process); the 62 single-facet combinations a reader
reaches in one click are pre-warmed at boot and answer in 0.9 ms.

Every `node:sqlite` call is synchronous on the one event loop, so that budget is
the containment, not a cure: five indexes, narrow-subquery sorts and the facet
memo are what keep it true. `CLAUDE.md` §Backlog states the three conditions
under which the worker thread gets built, and why it has not been.

### Security

This app takes passwords and runs multiplayer, so, plainly:

- **Passwords** are `node:crypto` scrypt (N=16384, per-user salt) compared with
  `timingSafeEqual`. The sessions table stores **only the SHA-256** of the token
  it hands out — the cookie `qarid_sess` (HttpOnly, SameSite=Lax, Secure
  whenever `PUBLIC_ORIGIN` is https, 90 days, rolling), or the Bearer token the
  Android shell asks for, which lives in the same table and is revoked
  wholesale on a password change. **There is no email, so there is no password
  reset** — the owner edits a row (see §Accounts).
- **The corpus database is opened `readOnly` + `query_only=1`** and is never
  written at runtime. `data/qarid-users.db` is the *one* writable database, and
  if it cannot be created the server logs a line, keeps serving the whole site,
  and answers `/api/auth/*` with 503.
- **`SameSite=Lax` is not a CSRF defence here**, because SameSite is computed on
  the registrable domain and this box hosts a suite of sibling subdomains whose
  pages carry `qarid_sess`. `server/origin.ts` is the guard: `Sec-Fetch-Site`
  must be `same-origin` or `none`, `Origin` (when present) must match, a body
  must declare `application/json`, and it covers every non-GET plus the `/ws`
  upgrade.
- **A room code is a name; `rooms.join_key` is the credential.** Six speakable
  letters are only 343,000 values, so `/join`, a non-player's `/state` and the
  socket all require the 24-character key that rides in the share link — or the
  host's explicit acceptance of a knock.
- **The socket authenticates on every command**, not just at the upgrade, and
  spends a frame budget keyed on the *user* (a per-socket counter is defeated by
  opening a second socket).
- **A hardening pass fixed 12 confirmed findings before the site went public** —
  each is named, one line each, in [`docs/releases/v2.0.0.md`](docs/releases/v2.0.0.md).

No claim beyond that: there has been no external audit, and the threat model is
a public read-mostly site with a handful of accounts, not a bank.

### Accounts

Everything the ديوان does is readable without an account; an account exists for
1v1 مساجلة and for a page with your name on it (`#/u/<username>`). It lives in a
**second, writable** database — `data/qarid-users.db`, `USERS_DB_PATH` — created
and migrated by `server/users.ts` (`PRAGMA user_version`, WAL, foreign keys on).

Registration is **open by default**. `REQUIRE_INVITE=1` closes it and
`INVITE_CODES=a,b,c` reopens it to those codes (with no codes set, to nobody).

To remove or rename an account, edit the row:

```sh
sqlite3 data/qarid-users.db "DELETE FROM users WHERE username = 'labid';"
# sessions, the arsenal snapshot and match rows go with it (ON DELETE CASCADE)
```

### The مساجلة socket

`/ws/room/:code` (`@hono/node-ws`) is **not** an `/api` path — it is an upgrade,
and the corpus gate would answer it with JSON no browser reads. A room is decided
entirely server-side: the clock is a column, the turn order is derived from the
`match_turns` rows and never from a counter, and an answer goes through the same
`verifyAnswer` the solo duel calls. Three things fall out of that and are not
features: a reconnect is just another `state` event, the polling fallback
`GET /api/room/:code/state` is the same snapshot the socket pushes (one code
path), and a dropped socket forfeits nothing, because the only thing that can end
a turn unanswered is a timestamp in the database.

The web upgrade is cookie-authenticated (a browser cannot set a header on a
WebSocket). The native shell has no cookie, so it offers its bearer as the
subprotocol `qarid.bearer.<token>`; the server reads subprotocol → header →
cookie down the same path. `vite.config.ts` proxies `/ws` with `ws: true` —
without that flag Vite answers the upgrade itself and dev silently falls back to
the poller while production works.

### PWA + Android

The web app is installable as-is: `client/public/manifest.webmanifest`, the gold
nib icons, `client/public/offline.html` and a hand-rolled service worker
(`client/sw/sw.ts`) versioned by the build hash — shell and fonts precached, API
network-first. The masthead grows an install affordance where the browser offers
one.

The Android app is Capacitor over that same built shell (`webDir: "dist"`, no
`server.url`, so the WebView never points at a remote page). App id
**`space.avicenna.qarid`**; the API base is baked in at build time via
`VITE_API_BASE`; `https://localhost` is on the server's CORS allowlist.

```sh
export JAVA_HOME="$HOME/Android/jdk-21.0.11+10"
export ANDROID_HOME="$HOME/Android/Sdk"

VITE_API_BASE=https://qarid.avicenna.space npm run build
npx cap sync android
android/gradlew -p android assembleRelease
# → android/app/build/outputs/apk/release/app-release.apk
```

Signing is read from `android/keystore.properties` (**gitignored**), which names
a keystore kept *outside* the repo and its credentials. When that file is absent
— a fresh clone, a contributor with no key — the release simply builds
**unsigned** rather than failing. Nothing about the key belongs in this file or
in any other tracked one.

`/.well-known/assetlinks.json` is served by Hono so
`qarid.avicenna.space/#/room/<code>` opens the app instead of the browser.

### Deploy

Ports: dev API **5750** · dev Vite **5751** · preview/smoke **6750** · prod
**8010**. 8010 is what the Cloudflare tunnel's ingress points at, so moving it
means editing the CF dashboard too.

```sh
cp .env.example .env          # HOST/PORT/PUBLIC_ORIGIN/DB_PATH/USERS_DB_PATH
ln -s "$PWD/deploy/qarid.service" ~/.config/systemd/user/qarid.service
ln -s "$PWD/deploy/qarid.service" \
      ~/.config/systemd/user/avicenna-suite.target.wants/qarid.service
systemctl --user daemon-reload && systemctl --user enable --now qarid.service
curl http://127.0.0.1:8010/healthz && curl 'http://[::1]:8010/healthz'
```

The server binds **both** `127.0.0.1` and `::1` — cloudflared resolves
"localhost" to `::1` first and dropping the twin bind 502s the tunnel. Both
listeners get the `injectWebSocket` handle, or one of them serves rooms that
never connect.

Cloudflare: the `cf-qarid` service in `~/containers/tunnels/docker-compose.yml`
(host networking, `${TOKEN_QARID}`). The tunnel itself and its public hostname
(`qarid.avicenna.space` → `http://localhost:8010`) are created by hand in the
Zero Trust dashboard.

**After changing client code**: `npm run build && systemctl --user restart
qarid.service`. The server reads `dist/index.html` exactly once, at boot — skip
the restart and every hashed asset 404s.
