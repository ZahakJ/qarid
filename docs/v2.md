# قريض v2 — owner feedback sprint (authoritative spec; extends design-ux.md/design-server.md; wins on conflict)

Owner's verbatim pain points: duel options opaque (esp. the bottom ones); didn't realize sadr-only input works; wants a tutorial/assist mode (type first word → app suggests matching corpus abyat, maybe regex); search CSS rough; poem-browsing fonts inconsistent, some content off-screen; the duel letter-well CSS possibly off; scrollbars "extremely lame" → themed; poets tab CSS should be "super epic"; whole app more animated; wants accounts/profiles; 1v1 مساجلة invite rooms with a chosen starting bayt; global Ctrl+F quick search for poems AND poets (dedicated search tab can be demoted; poets tab stays for filters).

## 1. Duel clarity (client)
- Every setup option gets a one-line plain-Arabic explanation VISIBLE (not tooltip-only): what the tier changes concretely («الخصم يجيب من مشاهير الأبيات فقط», …), what الوصال vs المبارزة means, what وضع السلسلة (روي vs الحرف الأخير حرفيًا) means with a live example rendered from a real bayt («كتابُهُ → الروي ب، والحرف الأخير ه»). Kill or rename any label a non-expert can't parse. The «القيود» and chain-mode rows (the "bottom ones") get the most attention.
- Sadr-only input must be UNMISSABLE: helper line under the textarea always visible («يكفي أن تكتب الصدر وحده — سنجد البيت»), and the placeholder shows a sadr-only example.
- «كيف تلعب» walkthrough: a 5-step overlay (from setup and from the rules page) that walks a real exchange with annotated screenshots/live components; first-ever visit to #/duel auto-offers it once (localStorage flag).

## 2. Assist / tutorial mode (server + client)
- New endpoint GET /api/game/assist?letter=<L>&q=<typed>&limit≤8: corpus abyat whose first_letter=L and whose normalized text matches the typed prefix/words (FTS prefix query: last token gets `*`), ranked by fame then bm25. Returns BaitDto list. Rate-limited with the game bucket.
- Duel setup gains وضع التدريب (assist) toggle (default ON for the first game, OFF thereafter): while typing in the answer box, after ≥2 chars a suggestion rail appears (debounced 250 ms) with up to 5 matching real abyat (fame-first); click fills the input. Scoring in assist mode: flat −50% and it says so. In normal mode the rail does NOT exist (hints only).
- Wildcard support in assist + global search: a trailing `*` on any word = FTS prefix (already safe through ftsQuery — extend it to allow the explicit trailing-star form). No full regex (3.4M-row scans); document the star syntax in the palette footer.

## 3. Global palette (client + tiny server)
- Ctrl+K AND Ctrl+F (and Cmd variants) open a global overlay palette on EVERY route (user explicitly asked to hijack Ctrl+F; Escape closes). `/` keeps focusing it too.
- Groups: أبيات · قصائد · شعراء (poets ranked with the fame-first rankedPoetRefs path), 5/4/4 max, arrow-mirrored nav, Enter opens, Ctrl+Enter opens #/search for the full list. Debounced 200 ms against /api/search scope=all (+ a new lightweight combined mode if needed).
- Masthead: replace the «البحث» nav item with a search affordance (⌕ + «ابحث ⌃K») opening the palette. #/search route KEPT for full results + deep links, just demoted from primary nav.

## 4. Accounts + profiles (server, new WRITABLE db)
- data/qarid-users.db (separate DatabaseSync, WAL, writable) — the corpus artefact stays readOnly (invariant). Tables: users(id, username UNIQUE COLLATE NOCASE, display_name, pass_hash (node:crypto scrypt, per-user salt, timingSafeEqual), created_at, last_seen), sessions(token_hash PK, user_id, created_at, expires_at, ua), match tables in §5. Migrations: PRAGMA user_version.
- Routes /api/auth/: register {username, displayName, password≥8} (open by default; if env REQUIRE_INVITE=1 then also {invite} checked against env INVITE_CODES comma list; 5/hour/IP rate limit), login (10/hr/IP), logout, me. Session cookie: qarid_sess, HttpOnly, SameSite=Lax, Secure when PUBLIC_ORIGIN is https, 90-day rolling. No email, no reset (owner can delete a row; note in README).
- Profile page #/u/<username>: display name, joined date, duel stats (from matches), best streak, arsenal snapshot IF the user opts to sync (POST /api/profile/arsenal snapshot json ≤8KB). Own profile editable (display name). Local (localStorage) stats remain the source for solo play; accounts exist primarily for multiplayer + identity.
- Client: settingsStore gains auth slice; masthead shows «دخول/حساب» → auth dialog; logged-in avatar (initial letter in a gold nib disc).

## 5. Multiplayer مساجلة rooms (the epic bit)
- Model: rooms(id/code 6-char speakable, host_user_id, guest_user_id NULL until join, starting_bait_id, mode rhyme|literal, timer_s NULL|30|60|90, status waiting|active|done, winner, created_at), match_turns(room_id, turn_no, user_id, bait_id, played_at, ms_taken). Both players MUST be logged in.
- Flow: host creates room from duel setup («ضد صديق») → picks the opening bayt (via palette search or عشوائي button, fame≥2 default) → gets a room code + share link (#/room/<code>). Guest opens link → joins. Server flips to active; HOST recites the starting bayt as turn 0; guest answers first. Turns alternate; each answer goes through THE SAME verify pipeline (strict, server-authoritative, exclusion list = all played bait ids + poem ids); wrong-letter/not-found = strike (3 strikes or timer expiry loses the duel; configurable strikes 1–3 at creation). Winner recorded; rematch button swaps roles.
- Transport: WebSocket via @hono/node-ws (install it) at /ws/room/<code>, cookie-authenticated on upgrade; events join/state/turn/verdict/timeout/end/rematch; server is the single clock (deadlines timestamped server-side; client renders countdown). Reconnect-safe: full state replay on join; a dropped socket does not forfeit until the timer actually expires. Polling fallback GET /api/room/<code>/state for resilience.
- Client: #/room/<code> view reusing the duel play components (exchange log, letter indicator, input, HUD showing both players + whose turn); spectator = anyone logged-in opening the link when full → read-only live view (cheap: same state feed, no input). Room list on profile (recent matches, W/L).
- Cloudflare tunnel passes WebSockets — verify through the public URL in the E2E pass.

## 6. CSS/animation overhaul
- SCROLLBARS: themed app-wide — thin (10px), track transparent ink, thumb gold-dim gradient with hover glow (scrollbar-color + ::-webkit-scrollbar*), including inner scroll areas (palette, facet rail, exchange log). Must stay usable; no scroll hijacking.
- SEARCH view: proper visual pass (result cards rhythm, highlight marks, facet strip alignment, count line).
- BROWSE/poem lists: ONE type scale for verse previews (Amiri at --fs-bayt-sm) and one for meta (--font-ui) — hunt the inconsistent font-family/size usages; fix any overflow/off-screen content at 1440/1024/390 (esp. long titles + bayt-mode cards).
- DUEL letter well: rebuild the «المطلوب/عندك» cluster CSS: perfect circles that don't distort (aspect-ratio, fixed inline-size), baseline-aligned Amiri letters, the timer arc concentric, RTL arrow correct, alsoAccepted ghost chips aligned; verify at 390.
- POETS tab "super epic": redesign pass — a hero letter rail with the active letter enlarged in Aref Ruqaa gold, poet cards with layered hover (lift + gold hairline sweep + bio reveal), era chip strip with counts, staggered entrance animation, letter section headers with the dissolving rule. Keep 76px virtualized row math or adapt useWindowedList accordingly.
- ANIMATION pass app-wide: staggered card entrances (60–80 ms, translateY 8px + fade), view-level fade/slide on route change, chip hover/active micro-transitions, letter-grid cells pop on hover, HUD score count-up, all gated by prefers-reduced-motion and never blocking input (>0 network work never waits on animation).

## 7. Non-negotiables
- shared/arabic.ts stays the single normalizer; corpus DB stays readOnly; users DB is the only writable one; all UI Arabic, Western digits 0-9 (owner decision); every new list paginated; every new route zod-validated + tested; done bar green + screenshot pass at 1440/390 before ship; commit granular.

## 8. Design-quality bar (owner: "super super smooth and correct… best design principles while being extremely creative")
- SPACING SYSTEM: one 4/8px scale (--sp-1..--sp-9: 4 8 12 16 24 32 48 64 96) — replace every ad-hoc margin/padding; vertical rhythm consistent inside every card/section; no magic numbers left in view CSS (component CSS may keep intrinsic sizes).
- ALIGNMENT: everything sits on the container grid — chip rows share baselines, card edges align across sections, hairlines span consistently; RTL logical properties only.
- EVERY UI agent must screenshot its own surfaces at 1440, 1024 and 390, READ the PNGs, and iterate until: no cramped or floating elements, no uneven gaps, no text touching an edge, no orphan line-heights, consistent corner radii (--r-1/--r-2 only) and shadow scale. "Looks fine" is not the bar; "would screenshot well on a design showcase" is.
- Transitions: 150–250 ms for micro, 300–420 ms for entrances, one easing family (cubic-bezier(0.22,1,0.36,1)); nothing bounces; nothing animates layout of text being read.
- Creativity is welcome ON THEME (ink, illumination gold, lapis, classical manuscript motifs — shamsa, corner pieces, dissolving rules) — never generic dashboard gradients or emoji.
