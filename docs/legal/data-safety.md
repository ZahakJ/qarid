# Play Console — Data Safety answers (قريض)

The exact answers to transcribe into **Play Console → App content → Data safety**
for the قريض app. Everything here matches what the code actually does
(`server/users.ts` stores it, `server/ratelimit.ts` reads the IP, the privacy
policy at `#/privacy` describes it). Owner-only blanks are marked `[OWNER: …]`.

The companion the form's "privacy policy URL" field wants is:

> **https://qarid.example.com/#/privacy**

and the in-app + web **account-deletion URL** (Play requires both a data-deletion
method reachable in-app AND a web URL) is the user's own profile-settings page:

> **https://qarid.example.com/#/u/&lt;username&gt;** → «احذف حسابي»

---

## 1. Does your app collect or share any of the required user data types?

**Yes** — it collects the data below. It does **not share** any of it with third
parties (no ads SDK, no analytics SDK, no third-party services at all).

## 2. Is all of the user data collected by your app encrypted in transit?

**Yes.** The app talks to `https://qarid.example.com` over TLS (Cloudflare
tunnel); the native shell uses a bearer token over the same HTTPS origin.

## 3. Do you provide a way for users to request that their data be deleted?

**Yes.** Deletion is self-serve, immediate and irreversible, reachable **in-app**
(profile → «احذف حسابي», password re-confirmation) **and on the web** at the
account URL above. It also removes sessions, avatar, published arsenal, and
settles/anonymizes match history. (Play form: "Users can request data deletion"
= yes; also offer the URL above in the deletion-URL field.)

## 4. Data types — mark each collected type

For every "Yes" below, the sub-answers are the SAME unless noted:

- **Collected?** Yes
- **Shared?** No
- **Processed ephemerally?** No (stored), except **IP address** = Yes (ephemeral)
- **Required or optional?** as noted
- **Purpose(s):** **App functionality** (and **Account management** where noted).
  NOT for advertising, analytics, personalization, or fraud-prevention SDKs.

| Play data type | Collected | Notes |
|---|---|---|
| **Name** | Optional | The optional **display name** («الاسم المعروض»). Purpose: App functionality, Account management. |
| **User IDs** | Required | The **username** (account identity, also the public `#/u/<name>` handle). Purpose: App functionality, Account management. |
| **Photos** | Optional | The optional **avatar image** the user uploads. Purpose: App functionality. |
| **App activity — in-app actions / other user-generated content** | Required* | **Gameplay & duel stats and room/match history** (the أبيات exchanged in a room, results, streaks). *Generated by playing; an account that never plays a room has none. Purpose: App functionality. |
| **App info & performance / other (Device or other IDs)** | — | **None.** No device identifiers, no advertising ID. |
| **Location** | — | **None.** |
| **Personal info — Email address / Phone / Address** | — | **None.** There is no email field, hence no password reset. |
| **Financial info** | — | **None.** No payments, no purchases. |
| **Messages** | — | **None.** (Room أبيات are game moves over public classical poetry, declared under App activity above, not private messaging.) |

### The one that isn't a clean form row: password

The app **collects a password** at account creation, stored **only as a scrypt
hash** (never plaintext, not recoverable). In the Play form this belongs under
**"User IDs" / account creation** as a credential used for **Account
management**; it is never shared and is deleted with the account. If Play's UI
offers a "Credentials" or "account creation data" nuance, select it there.

### IP address

Used **transiently, at request time**, for rate-limiting and abuse-prevention
(`server/ratelimit.ts`), keyed on `CF-Connecting-IP`. It is **not** stored as a
per-user log. If the form forces an IP row, mark it **processed ephemerally**,
purpose **App functionality / preventing fraud & abuse (service integrity)**,
**not shared**.
