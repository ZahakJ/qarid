# Amendments — merged from a second independent design pass (these override design-server.md / design-ux.md where they conflict)

1. **Two chain modes stored per bait, one displayed.** Store `rawiyy` (peeled الروي, classical) AND `last_letter` (literal final letter, "street rules"). Game setting `mode: 'rhyme' | 'literal'` (default 'rhyme'). In 'rhyme' mode verify accepts either letter (leniency); in 'literal' mode only last_letter. UI always shows the required letter explicitly with its provenance word underlined in lapis.
2. **`combo_counts(first_letter, era_id, meter_id, tier, n)` WITHOUT ROWID** materialized at ingest → setup screen shows live eligible-pool counts instantly and `/api/game/reply` can short-circuit an exhausted combination without a scan.
3. **Playability predicate** for game_baits (stricter than length≥8): both halves 12–80 chars after stripping, length ratio 0.5–2.0 (catches tadwir splits), letters resolve, no ASCII/digits/placeholder runs, lang ≠ عامي.
4. **Deterministic rebuilds**: per-bait `bucket`/`rand` derived from a hash of (poem dedup_key, position), not of autoincrement id, so a rebuild yields the same daily bayt.
5. **`tailBias`** on `/api/game/reply`: `'easy'|'none'|'hard'` — the real difficulty lever. easy avoids replies whose rawiyy ∈ rare {ظ ذ غ ز ث ض ص ط خ}; hard prefers them and prefers `opens_conj=0` baits (store `opens_conj` = sadr starts with bare و/ف).
6. **Daily opponent is seeded**: reply seed = `${dailySeed}:${turn}` so everyone faces the same chain on `#/daily`.
7. **near_miss tier** in verify: FTS score band 0.35–0.60 → `reason:'near_miss'` with one `suggestion` bait and an «اقبل هذا البيت» button costing −25 pts (distinct from `not_found` which only shows «هل تقصد؟» list). Fairness: time spent in verifying/rejected is added back to the deadline; timers wall-clock anchored.
8. Extra hint «بدّل الحرف» −150 + streak reset (server picks a new required letter from a random famous bait) — a mercy option so a duel never dead-ends on ظ.
9. `GET /api/poems/:id/similar` (same poet+meter+rhyme, then same meter+rhyme) — cheap, powers «قصائد على الوزن والقافية» on the poem page.
10. `/api/meta` includes per-letter `{startsWith, endsWith}` corpus counts → arsenal "weakness = endsWith-demand × (1 − supply/8)" and browse letter-grid counts without a facets call.
11. Themes: قصيرة/عامة are *buckets* (kind:'bucket'), hidden from the theme filter chips but still browsable via URL. Eras carry `kind: 'period'|'region'` (الأندلس والمغرب is a region).
12. Poem page for >300 abyat: `content-visibility:auto` per bait row instead of virtualization (keeps Ctrl+F, anchors, selection). `?bayt=n` deep links.
13. Client pre-check on wrong letter = no server call (instant feedback); server remains authority on accept.
14. Search highlight: parse »« into `<mark>` styled as lapis **underline**, not background fill.
15. `<bdi>` around every interpolated data string in mixed-direction contexts; `←` = next, `→` = previous in RTL.
16. Scoring: `base × streakMult + timeBonus + obscurityBonus(log poet poem_count)`; stuck opponent («أفحمتَ الخصم») = +500.
17. Idempotency test: ingest the fixture twice → byte-identical row sets.
18. **~~One numeral line, written out.~~ SUPERSEDED by amendment 25** — the two-scale split (Arabic-Indic for prose, Latin for the game's instruments) is gone; the app writes Western digits everywhere. What survives of it: one strip, one scale — the HUD a player watches as «النقاط 320» must not hand them a different-looking number on the summary — and `--font-mono` is Plex Mono's LATIN subset, which is now the point rather than the hazard.
19. **The بيت's centre channel is the gutter, not the tracks' slack.** Both شطر are pulled to the inner edge of their reserved track (`justify-self: end` / `start`) and the poem measure is 54rem. Outer alignment (design-ux.md §3 as written) measured 0.61 track fill and a 408px void between two 265px hemistichs — a gap wider than the verse, with both inner edges ragged in opposite directions. Below 860px the بيت is one column and both are `justify-self: stretch`, unchanged.
20. **No «الأحدث» browse sort.** The corpus carries no date on a قصيدة; the عصر facet is the only honest answer to "when". design-ux.md §3's four-sort list becomes three: الأشهر · الأطول · عشوائي.
21. **A reload is not a fresh turn.** `RESUME` carries the STORED deadline forward plus a fixed `RESUME_GRACE_MS` (3 s), never past `turnSeconds`; a deadline that expired while the tab was shut lands as an ordinary `TIMEOUT`, life and all. The clock is the entire difficulty of فحل and سيف — `clampTier` only offers them while the timer is on — so handing back a whole turn on F5 made the timer optional.
22. **§7's pause credit is capped for the cards the PLAYER holds.** `verifying` is the server's pause and is still credited in full. `rejected` and `disambiguating` are not: those cards stay up until they are answered or dismissed, so their span is credited at most `MAX_PAUSE_CREDIT_MS` (5 s) — and `timeLeft` shows the clock running again past it, so a half-remembered بيت is no longer an unlimited pause button on سيف. `RESUBMIT` settles the card's pause (capped) before opening the server's own.
23. **A card never locks the field.** The answer textarea stays live under a `near_miss`, an ambiguity card and a lost-life card; answering again dismisses the card and goes through `RESUBMIT` (or `RESOLVE` then `SUBMIT`). Before this, retyping a correct بيت under a near-miss card did nothing at all — no toast, no shake, no request — and the «هل تقصد؟» chips filled a field that was greyed out.
24. **Every shortcut is matched by keycap, not by character.** `useKeyboard` resolves `logicalKey(e)` — `e.key` when it is already ASCII or a named key, `e.code` otherwise — so the map in `client/data/shortcuts.ts` fires on the Arabic layout, where the physical J emits «ت», G emits «ل» and Shift+/ emits «؟». The `<kbd>` labels are keycap legends; the ← / → pair stays, being real legends and not Bidi_Mirrored.
25. **WESTERN DIGITS EVERYWHERE (a deliberate decision).** Every number a reader sees is `0-9`, grouped with a comma every three: «239,411 قصيدة», «951 بيتًا», verse number «12», «×2», «24 آب», the daily share block, the إحصاءات tiles and bars, the ترسانة ring, the clock. `shared/format.ts` is the one formatter and no longer takes a numeral scale; `toArabicDigits`, `ARABIC_THOUSANDS` (U+066C), `ARABIC_DECIMAL` and the `numerals: 'arabic'|'latin'` setting are DELETED — the toggle was never surfaced in any settings UI, so removing it was cheaper than keeping a second rendering path alive, and a persisted slice that still carries the key is stripped by zod on load. `toLatinDigits` stays, to PARSE digits a reader types. Two consequences worth knowing: (a) `.bayt-num` moved from `--font-verse` to `--font-mono`, because the Amiri we ship is the `arabic` subset and has no Latin figures at all — the margin number was falling through to whatever serif the OS had; (b) a NEUTRAL character glued to a number needs its own LTR run under RTL — «×2» (HUD), «1200 × 630» (share dialog) and «2–3» (stats histogram) carry `dir="ltr"`, while a leading LRM already fixed «+152» / «−40» by rule W7. The أطوال القصائد bin captions are now DERIVED from `min`/`max` by `histogramLabel()` instead of read from `meta.stats_json`, so the Arabic-Indic labels baked into an artefact built before this date do not leak onto the stats page and no re-ingest is required.
26. **وضع القراءة is a ROUTE, and it REPLACES the ديوان entry.** `#/poem/<id>?read=1` (design-ux.md §3's «حجم الخط» toolbar gains «اقرأ» beside it, and the phone gets a full-measure «اقرأ القصيدة» where its toolbar is not rendered) hands the whole screen to the قصيدة: masthead, app bar, tab bar and footer all stand down, on the desktop as well as the phone. Three decisions inside it. It is a route rather than component state, so browser back, hardware back and a shared link all work with no code of their own, and `pageKey` drops the flag so entering and leaving is not «a new page» to the scroll rule. It renders INSTEAD of the قصيدة page rather than floating over it — two copies of a 905-بيت قصيدة is two of every `id="bayt-N"` anchor, and the page's own scroll offset is what the second copy would have been keeping, so it is captured at the press and given back on the way out. And it adds no new setting: the three sizes are `settings.verseSize`, the قصيدة page's own persisted choice, and `reader.css` re-declares the `--fs-bayt-*` scale those three names resolve to rather than inventing a fourth size — `BaytPlate` is untouched and stays the only بيت renderer. `body[data-immersive]` now carries a VALUE (`game` for a مساجلة, `read` for a reading), because phone.css's docked game measures and reader.css's must never land on each other's screen.
